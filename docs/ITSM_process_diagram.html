How it works now (push): a ticket arriving is the only event the 1.1 Validator waits for. After it validates the type it calls the right lane directly — the Request lane (RITM-Generator → Validation → Approval → SCTASK-PJ-Bridge, each HTTP-calling the next) or the Incident lane (Triage-Orchestrator + Major-Incident-Detector). Both lanes converge on the 4.1 Dispatcher, which checks the kill switch + idempotency and then routes the job by JobType to exactly one executor (the six no longer poll — they are called). When an executor finishes it calls the 6.2 PJ-Ticket-Resolver (agent path) or the bridge → 6.1 SCTASK-Orchestrator (request path), which closes the ticket. Every called flow re-reads its row live first, so a stale trigger snapshot can no longer revert a resolved ticket or skip a job.

AI surface area: cre79_agent in 2.1 Triage-Orchestrator, 3.2 RITM-Validation-Triage (with its FindGroup tool) & X1 Major-Incident-Detector · T1 SearchKnowledgeBase Copilot Studio skill. The Clarifier (1.2) is deterministic — not AI.
